# V4.5 DICOM 导入

医生流程：**导入 DICOM → 选择文件夹 → 选择序列并核对患者、检查和 T1 类型 → 勾选确认 → 转换并载入 → 检查完整 MRI → 手动开始建模**。

列表不默认选择序列，切换序列清除确认。显示患者姓名、编号、检查日期、序列号、描述／协议、模态、文件数、矩阵／帧数及图像类型。样本预览不作 T1 判定，未重排解剖方向，也不代表完整头部覆盖。文件数不等于多帧 DICOM 的切片数。

## 实现与打包

- `core/dicom_import.py`：使用现有 SimpleITK/GDCM 扫描，不依赖扩展名；按患者编号、Study UID 和 Series UID 分组。转换前逐文件复核归属，将所选序列复制到独立临时目录，避免将混合目录整体转换。
- `ui/dicom_import.py`：后台扫描、预览和转换；取消时停止任务并等待线程结束。只允许 MR；勾选人工确认后才能转换。取消导入或取消结果选择不替换主界面的 MRI。
- 内置官方 `dcm2niix` Windows x64，发布标签 `v1.0.20250506`，二进制自报 `v1.0.20250505`。文件、来源、SHA-256 及许可位于 `assets/dcm2niix/`，发布包位于 `_internal/assets/dcm2niix/`。
- 显式忽略用户注册表中的转换默认设置，使用内置 gzip；不强制合并不同回波，不生成 BIDS JSON。原始 DICOM 不修改。转换结果及日志保存到程序下 `NeuroGuide/dicom_imports/<唯一目录>/`，仍属于需要按患者资料管理的文件。
- 验证输出为可读取的三维体积、有有限且非退化的仿射矩阵、有效灰度。转换警告必须再次确认，默认取消载入；多份可用输出必须再次选择。四维、平面或无效输出不直接导入。
- 转换成功接入原有 `select_mri`，只执行模型缓存检查；生成模型仍需医生点击。新增两个项目模块继续使用 Cython 保护，PyInstaller 收集转换工具和许可。

## 验证范围

2026-10-30：135 项原生模块回归通过，Qt 回调异常为 0，58 个原生模块的发布审计通过。验证混合 T1/T2 目录只转换选中序列、患者／序列归属不一致时拒绝、取消清理、切换序列重新确认、警告确认及多输出选择。

清理 Python/Conda 环境路径后，打包程序完成实际按钮与后台线程的扫描、选择、勾选、转换、MRI 载入和缓存检查。转换结果逐体素验证像素及物理坐标，确认没有开始预测。GUI/Worker 启动与 GPU/隐藏 GPU 自检通过。

测试影像为生成的 classic MR DICOM，包含两个序列及无 `.dcm` 后缀的文件。尚未完成不同厂家设备实际数据、增强型多帧、不同压缩传输语法及不完整序列的兼容性验证。软件能够读入或完成转换，不等于影像已通过建模质量评估；医生仍需核对影像归属、序列类型、覆盖范围、质量与方向。

日志与截图：`build/dicom_release/validation/`。原生回归：`build/dicom_native_tests.log`。本次改动不改变分割、导联场、TI/tES 算法，历史完整 MRI 推理验收保留；新增导入和启动检查另行记录到 `docs/release_V4_5_validation.json`。
